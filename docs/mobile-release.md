# スマートフォン版の準備と安全な統合

## 現在の公開状態

この変更は公開準備のみ。Pages設定変更、リポジトリ公開範囲変更、デプロイ、mainへのマージは実施していない。
GitHub Pagesを第一候補とする。GitHub Freeの公開リポジトリで利用でき、追加サービスのアカウントは不要。
非公開リポジトリの場合はプランの対応可否を確認し、Pagesのためだけに公開範囲を変更しない。
静的サイトは端末・ブラウザーごとの独立したゲームであり、オンライン共有ワールドではない。

## PRの依存関係

1. PR #1: `codex` → `main`。基本ゲームとUI改善。
2. PR #2: `npc-dungeon-runs` → `codex`。NPC探索と競売精算。
3. 今回: `mobile-play-readiness` → `npc-dungeon-runs`。スマホ操作、保存、公開準備。

承認後、#1を通常のmerge commitで統合する。続いて#2のbaseをmainへ変更し、差分・テストを確認して統合する。
最後に今回のPRのbaseをmainへ変更して同様に確認する。
積み上げPRの祖先を維持するため、途中でsquash/rebase mergeを使わない。
squashを選ぶ場合は後続を新しいmainへrebaseし、重複差分がないことを確認する必要がある。
各段階で `npm ci`、`npm test`、`npm run build`、`git diff --check` を実行する。

## 公開の承認後に行う設定

1. Settings → Pages → SourceをGitHub Actionsにする（管理権限が必要）。
2. `github-pages` Environmentはmainのみを許可し、可能なら承認者を設定する。
3. mainに全コードが統合されたことを確認する。
4. Actionsで `Publish approved static game` をmain指定で手動実行する。
5. deploy jobが返すURLをiPhone Safariで開く。実行前には利用可能なプレイURLはない。

公開workflowはpush/PRで実行されず、手動実行でもmain以外はスキップされる。
通常CIはテストとビルドだけで公開しない。Viteの相対asset URLによりプロジェクト配下でも読める。

## 保存の扱い

プレイヤーは従来の `ayakashi-no-kuni.save` キーと形式を維持。
NPCは別キー `ayakashi-no-kuni.npcs.v1` のversion付きsnapshot。描画やロジックから保存先を分離した。
NPCはプレイヤーの操作時だけ進行し、ページを閉じた間の進行やサーバー定期tickはない。
保存不可時は画面に警告し、プレイ操作は継続できる。
URLのorigin変更（プレビューからPages等）は別保存になる。Safariのプライベートブラウズやサイトデータ削除では保存を失い得る。
二つのsnapshotの更新は原子的ではない。将来のサーバー版では共有worldのtickと経済をトランザクションで保存する。

## 機能の現状

| 分野 | 実装済み | 仮実装・不足 |
| --- | --- | --- |
| 職業・スキル | Lv.3/80文で転職、技習得、MP、攻撃/防御/回復/LUK技 | 職業別statGrowthデータはレベルアップで未使用。熟練度・技の成長なし |
| LUK・業 | LUKは探索希少品、通常会心、幸運技、賭場へ適用。業は回復術補正/術使用条件 | 業のプレイ中変動は賭場大当たりのみ。装備effectsのdropRate/skillCost/karmaGateは未適用 |
| 装備 | 武器攻撃+強化、防具防御、装飾LUK、装備切替 | 職業装備制限や業装飾の実効補正は不足。複数同名装備はUIで個体選択不可 |
| 素材・鍛冶 | 探索/敵/宝箱の素材、鉄鉱石2個と文で武器強化 | 製作・合成・防具/装飾強化なし |
| 店舗・競売 | 町店舗の購入/売却UI、競売出品/入札/返金/精算コマンド | 競売UIなし。店舗在庫数量・価格は静的。装備中品売却の扱いに改善余地 |
| NPC・経済 | 部屋探索、戦闘、撤退/敗北/帰還、報酬/成長/装備更新、snapshot保存 | 市場需給計算はNPC/店舗取引と統合されていない。共有経済・NPC入札なし |

次の小さな開発候補は、装備個体の識別と売却整合性、職業成長値の適用、既存素材を使う製作の順。
職業成長はバランス変更になるため、既存の初回ダンジョン回帰テストを伴って別段階で扱う。
新ダンジョン・町・アイテム追加は今回行わない。

## スマホ回帰チェック

実機Safari、または390×844 viewportで以下を確認する（今回のクラウドブラウザーはlocalhostへ接続できず未実施）。

- document.scrollWidthがviewport幅を超えない：3タブ、町、地図、戦闘、荷袋展開、NPC。
- タブ3個が横スクロールなしで押せ、選択が明確。
- 北南東西の54px方向キーで移動でき、未探索名が隠れる。戦闘中は移動なし。
- 戦闘ボタン・ショップ売買ボタンは最低44px高。購入結果を店舗内で確認できる。
- 装備を展開して操作した後も展開を維持し、強化値が失われない。
- HP/MP/文/経験/位置を記録し、reload後に一致する。NPC進行刻も一致する。
- ボス報酬・帰還・再入場、Safariサイトデータ消去をせず再訪して保存確認。
